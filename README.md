# PDP-11 CPU & Peripheral Emulator v1.0 by Roman Krol

Высокоточный эмулятор 16-битного микропроцессора архитектуры PDP-11 (LSI-11), написанный на языке C. Проект включает в себя полноценное арифметико-логическое устройство (АЛУ), кастомный фреймворк автоматического изолированного тестирования и эмуляцию периферийных устройств ввода-вывода (Memory-Mapped I/O).

## 🚀 Основные возможности эмулятора

*   **Полная эмуляция ОЗУ (64 Кб)**: Реализован побайтовый (`b_read`/`b_write`) и пословный (`w_read`/`w_write`) доступ к памяти с проверкой четности адресов и границ ОЗУ.
*   **Все 8 канонических мод адресации**: От регистровой (Мода 0) до индексной косвенной со знаковым расширением смещений (Мода 7). Вычисление эффективных адресов полностью отделено от логики АЛУ.
*   **Железные правила PC и SP**: Аппаратная защита указателя стека `SP` (R6) и счетчика команд `PC` (R7) — изменение адреса для них всегда строго равно 2 байтам, даже при выполнении байтовых инструкций.
*   **Изолированная периферия (MMIO)**: Реализована аппаратная изоляция портов дисплея. Регистр состояния `OSTAT` (0177564) всегда рапортует о готовности устройства (`0200`), а запись в регистр данных `ODATA` (0177566) перехватывается и канонично выводится на экран терминала.
*   **Гибкий многоуровневый логгер**: Централизованная система `print_log` с поддержкой уровней логирования от глубокой трассировки шагов АЛУ до полной тишины. Уровень по умолчанию — `LOG_INFO`.

## 🛠️ Поддерживаемый набор инструкций

Эмулятор полностью поддерживает широкий набор словесных и байтовых инструкций:

*   **Арифметика и пересылки**: `MOV`/ `MOVb`, `ADD`, `SUB`, `CMP` / `CMPb`, `TST` / `TSTb`, `CLR`/ `CLRb`, `INC` / `INCb`, `DEC` / `DECb`, `NEG` / `NEGb`
*   **Многоразрядная математика и EIS**: `MUL` (Умножение), `DIV` (Деление), `ASH` (Арифметический сдвиг), `ASHC` (32-битный сдвиг пары регистров), `ADC` / `ADCb`, `SBC` / `SBCb`, `SXT` (Расширение знака флага N)
*   **Сдвиги и побайтовый обмен**: `ASL`/ `ASLB`, `ASR`/ `ASRB`, `ROL` / `ROLB`, `ROR` / `RORB`, `SWAB` (Побайтовый обмен в слове с флагами по младшему байту)
*   **Побитовая логика**: **Побитовая логика**: `BIC` / `BICB` (Сброс битов по маске), `BIS` / `BISB` (Логическое ИЛИ / установка битов), `BIT` / `BITb` (Логическое И — проверка битов без записи), `COM`/ `COMb` (Инверсия), `XOR` (Исключающее ИЛИ регистра и памяти)
*   **Управление флагами PSW**: `CCC`, `CLC`, `CLN`, `CLV`, `CLZ` (Очистка флагов), `SCC`, `SEC`, `SEN`, `SEV`, `SEZ` (Установка флагов по маске младших бит)
*   **Безусловные переходы и подпрограммы**: `JMP` (Аппаратный переход с запретом Моды 0), `JSR` / `CALL` (Вызов функций), `RTS` / `RETURN` (Симметричный возврат из подпрограмм через стек)
*   **Команды ветвления (Условные относительные переходы)**: `BR`, `SOB` (Цикл уменьшения регистра), `BCC` / `BHIS`, `BCS` / `BLO`, `BEQ`, `BNE`, `BPL`, `BMI`, `BVC`, `BVS`, `BGE`, `BLT`, `BGT`, `BLE`, `BHI`, `BLOS`
*   **Системные команды**: `NOP` (Холостой ход), `RESET` (Сброс внешней шины), `HALT` (Штатный останов CPU)

## 🚨 Системные коды завершения (Exit Codes)

В эмуляторе реализована сквозная промышленная система контроля статуса завершения (`ExitCode`) на базе макроса `EMULATOR_EXIT`. Для аппаратных ошибок ядра коды привязаны напрямую к **оригинальным адресам векторов аппаратных трапов процессора PDP-11 компании DEC**:

*   `0` (`EXIT_SUCCESS_HALT`) — Успешное выполнение программы, корректный останов по инструкции `HALT`.
*   `1` (`EXIT_TEST_FAILED`) — Сбой при выполнении автоматического юнит-теста в режиме проверки фреймворка.
*   `4` (`EXIT_MEM_ALIGNMENT`) — Трап по вектору 4 (Bus Error): попытка обращения по нечетному адресу при словесной операции.
*   `10` (`EXIT_MEM_BOUNDS`) — Трап по вектору 10: обращение по адресу за границами доступной оперативной памяти (`MEMSIZE`).
*   `11` – `14` — Критические ошибки файловой системы: повреждение структуры данных, неверный байт в блоке или ошибка доступа к объектному файлу `.pdp.o`.

## 🧪 Тестовый фреймворк

В проект встроен автономный движок автоматического тестирования, покрывающий **55 изолированных тест-кейсов**:
1.  **Стерильность выполнения (Teardown)**: Каждый тест оснащен процедурой `reset_cpu_state()`, что полностью исключает эффект «отравления» тестов остаточными флагами.
2.  **Математика АЛУ**: Проверка всех логических, арифметических и сдвиговых инструкций, включая бронебойную динамическую валидацию побайтового обмена `SWAB` против Си-архитектуры.
3.  **Логика ветвлений**: Монолитное тестирование всех комбинаций знаковых и беззнаковых флагов регистра состояния `PSW` (`NZVC`).

## 📦 Сборка и запуск проекта

Для сборки проекта вам понадовятся компилятор `gcc` и утилита `make`. Проект собирается с жесткими флагами безопасности, адресации и утечек памяти (`-fsanitize=address,undefined`).

### 1. Компиляция эмулятора
```bash
make
```

### 2. Запуск автоматических тестов (Все реализованные тесты)
```bash
./build/pdp11 --testall
```

### 3. Запуск одиночного теста по ID с флагом пошаговой трассировки АЛУ
```bash
./build/pdp11 --test 43 -trace
```

### 4. Доступные флаги логирования (управление выводом)
*   `-logoff` или `-quiet` — Полная тишина, только чистый вывод дисплея эмулятора (`PDP11 OUTPUT`).
*   `-error` — Выводить только критические ошибки эмуляции и сообщения о падении процессора.
*   `-info` *(По умолчанию)* — Общая информация о работе (загрузка блоков, приветствие, рамка останова).
*   `-trace` — Пошаговая трассировка выполнения инструкций Macro-11 с target-адресами переходов и дампом регистров `R0-R7` на каждом шаге.
*   `-debug` — Максимально глубокий отладочный лог ядра.

### 5. Пример запуска бинарного файла скомпилированной программы
```bash
./build/pdp11 test/zachet/putoct_plane/putoct_plane.pdp.o -trace
```

## 📂 Структура исходного кода

*   `src/config.h` — Конфигурация размеров памяти (`MEMSIZE`), таблицы типов данных (`Word`, `Byte`) и глобальных флагов.
*   `src/cpu.h` / `src/cpu.c` — Декодер инструкций (`parse_cmd`), логика вычисления эффективных адресов (`get_operand`), универсальные функции-обработчики АЛУ, централизованная карта `ExitCode` и диспетчер логов трассировки.
*   `src/memory.h` / `src/memory.c` — Физическая оперативная память, жесткая аппаратная изоляция портов дисплея (`OSTAT`/`ODATA`) через Memory-Mapped I/O, а также проходной загрузчик объектных `.pdp.o` файлов.
*   `src/logger.h` / `src/logger.c` — Многоуровневый системный логгер с фильтрацией вывода и строгой валидацией типов данных.
*   `src/tests.h` / `src/tests.c` — Таблица регистрации, изоляция контекста виртуальной машины (`reset_cpu_state`) и реализация **55 автоматических юнит-тестов** для сквозной проверки всех режимов ядра.
*   `src/main.c` — Главная точка входа, инициализация виртуальной машины и безопасный двухпроходный разбор аргументов командной строки.
